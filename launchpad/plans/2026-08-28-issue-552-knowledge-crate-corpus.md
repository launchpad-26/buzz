OPEN      1. #552's DoD says "representative architecture, capability, operational and
          reference nodes render." Verified against `node.schema.json` and a full scan
          of `origin/launchpad`'s corpus: the 13-value `type` enum has no `reference`
          member at all, and zero nodes of type `capabilities` or `operations` exist
          today (only `architecture`, 47 nodes, and `governance`, 20 nodes, do). This
          plan reads the bullet loosely — build a `type`-agnostic renderer, demonstrate
          it against the two types that actually exist, and let `capabilities`/
          `operations` nodes render automatically once authored — rather than literally,
          since literal satisfaction is not possible against today's corpus. Flagged for
          confirmation, not resolved by this plan.
          2. Whether the Settings panel should read the packaged corpus via the Rust
          `knowledge` crate through Tauri IPC, or via a directly-shared static asset
          (step 5's choice). #551's own `AGENTS.md` names the Tauri-wiring question as
          explicitly unresolved; going through IPC means editing
          `desktop/src-tauri/Cargo.toml`, a file ADR-0045's granted exception does not
          cover — a larger, undecided architectural change this plan avoids taking on
          inside one task. This plan's static-asset choice is a proposal, not a settled
          decision.
          3. The exact shape and location of the generated artifact
          (`launchpad/crates/knowledge/generated/corpus.json` and its frontend copy) is
          this plan's proposal; no prior art in the repo fixes it.
          4. The branch recommendation above (wait for #551 to merge) assumes #551
          merges in a reasonably short window. If it stalls, revisit the fallback
          described there rather than defaulting to a stacked PR.
