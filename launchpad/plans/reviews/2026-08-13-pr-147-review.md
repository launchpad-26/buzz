## Findings

### P1 — the credential probe rejects the intended Actions token

The plan requires `GET /user` to return 200 before proceeding:

`launchpad/plans/2026-08-12-issue-117-review-dimensions.md:510-530`

However, `GITHUB_TOKEN` is a GitHub App installation access token, while GitHub
documents `GET /user` as supporting GitHub App user access tokens and
fine-grained personal access tokens, not installation access tokens. A valid
workflow credential can therefore return 403, causing every production review
to be classified as an infrastructure failure.

The plan should use an endpoint that supports installation access tokens and
test the probe inside GitHub Actions.

References:

- <https://docs.github.com/en/actions/concepts/security/github_token>
- <https://docs.github.com/en/rest/users/users?apiVersion=2026-03-10#get-the-authenticated-user>

### P1 — `concurrent.futures` cannot terminate a hung reviewer

STEP 6 requires a hanging reviewer to time out and the process to terminate:

`launchpad/plans/2026-08-12-issue-117-review-dimensions.md:708-724`

Timing out `Future.result()` does not stop the running callable. Running futures
cannot be cancelled, and Python will not exit until executor work finishes. The
specified `concurrent.futures` design therefore cannot guarantee the required
termination behavior.

The plan needs a killable isolation boundary, such as one subprocess per
reviewer with explicit terminate/kill behavior, and a control using a genuinely
non-returning worker.

Reference:

- <https://docs.python.org/3.12/library/concurrent.futures.html>

### P3 — the GATES history contains a truncated sentence

`launchpad/plans/2026-08-12-issue-117-review-dimensions.md:1007-1009`, the text
“the settlement in” runs directly into “One change here…”. This leaves the
status and provenance claim incomplete and should be repaired.
