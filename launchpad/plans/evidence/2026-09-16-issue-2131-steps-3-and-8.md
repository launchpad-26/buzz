## What this run changed in the contract

**The blank line in gate three's response is why §2b now discards blank lines.** As first
written, verdict-last required exactly two lines, and this response has an empty line
between reason and verdict — three lines, a parse failure. It would still have blocked
the write, but the finding would have read "unparseable" instead of naming the verdict.
Four earlier verdict-last dispatches emitted no blank line, so the behaviour is
intermittent, which is worse than consistent: roughly one run in five would fail to parse
for a reason unrelated to the claim. §2b now discards blank lines before counting, which
costs none of its protections — narration lines are not blank, and the verdict line must
still equal a literal.
