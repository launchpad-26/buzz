# `web/`: implementation reference

This node documents `web/` (package `buzz-web`) -- the Vite + React 19 +
TypeScript single-page application in this repository's OSS source tree --
as the concrete code-level realization of the container architecture that
`architecture-containers-web` (`launchpad/docs/corpus/architecture/containers/web.md`)
describes: a browser client with no server process of its own, served
entirely by `buzz-relay`'s HTTP router. Where that node establishes *what*
the container is responsible for and *why* its runtime boundary is unusual,
this node establishes *how* the code realizes that: the build tooling, the
app's own entry point and routing wiring, and the exact relay-side code path
that turns a compiled bundle into what a browser actually receives.

## Target

**Target:** `architecture-containers-web` (`launchpad/docs/corpus/architecture/containers/web.md`),
a merged corpus node describing the `web` container's responsibility,
technology, interfaces, deployment, data, and security implications. This
node narrows to the subset that node's own *Scope and omissions* table names
as not yet covered in depth -- the app's build tooling and entry point, and
the specific relay router code path that serves it -- without restating that
node's interface catalogue, deployment narrative, or security analysis.

A reader can open the target directly at

`web/index.html`, `web/src/main.tsx`, `web/src/app/App.tsx`,
`web/src/app/router.tsx`, and `crates/buzz-relay/src/router.rs` /
`crates/buzz-relay/src/config.rs`.

## Divergences

**One structural quirk found, not a behavioral divergence.** `is_git_web_gui_path`
(the predicate `should_serve_spa` uses for the git-browser gate) matches `/`,
`/repos`, and `/repos/*`, which reads as though `/` is served through the
generic `spa_fallback` service like `/repos` is. It is not: `/` is registered
as its own explicit axum route to `nip11_or_ws_handler` *ahead of* the
fallback, so that handler -- not `should_serve_spa` -- decides what a request
to `/` gets, via its own independent `serve_git_web_gui` check.
`nip11_or_ws_handler`'s own comment states this explicitly ("`/` is an
explicit relay route, so it never reaches the SPA fallback"). The net
behavior for a plain browser `GET /` request is the same either way (bundle
`index.html` when `serve_git_web_gui` and `web_dir` are both set, otherwise
not), so this is not a functional bug -- but `is_git_web_gui_path`'s `/` arm
is unreachable through `should_serve_spa` in the router as currently wired,
which is worth a reader knowing before assuming the two code paths for `/`
agree by nothing more than coincidence. No test in `router.rs` exercises
`should_serve_spa("/", true)` through the actual merged router (only the
predicate function directly), so whether the two independent code paths stay
in agreement under future changes is not itself verified by anything found
here -- see *Scope and omissions*.

No other divergence between this implementation and the target container
node's description was found: the build tooling, entry point, and relay
serving mechanism described above match what `architecture-containers-web`
states, checked directly against both the app's source and the relay's
router/config code at this node's recorded revision rather than assumed from
that node's own (earlier-revision) citations.

## Verification

- **Automated relay-side unit tests** in `crates/buzz-relay/src/router.rs`
  assert `should_serve_spa`'s truth table directly (see the cited evidence
  entry above) and, in a separate test group (`spa_state`, `write_bundle`),
  exercise the merged router end-to-end against a temp directory standing in
  for `web_dir`/`admin_web_dir`.
- **Automated browser E2E** via `web/tests/e2e/smoke.spec.ts`, run through
  Playwright's `smoke` project against a built-and-previewed bundle
  (`pnpm build && playwright test --project=smoke`), asserts the home page
  renders Buzz branding and a "Repositories" section, and that the invite
  flow gates on age/legal consent.
- **Manual/CI build verification**: `Justfile`'s `web-build` and `web-check`
  targets (`tsc`/`vite build`, Biome lint/format) run in `just ci`; a failing
  `tsc` or `vite build` step fails CI before any runtime behavior is
  exercised.
- **Not verified by anything found**: no test was located that exercises the
  `/` route's two independent code paths (`nip11_or_ws_handler` directly, and
  `is_git_web_gui_path`'s inclusion of `/` inside `should_serve_spa`) together
  through the same running router to confirm they cannot diverge under a
  future change to either function in isolation.

## Scope and omissions

**This node covers** `web/`'s build tooling (Vite, TypeScript, the TanStack
Router code-generation plugin), its single entry point (`index.html` +
`main.tsx` + the provider stack it mounts), its routing shell (`App.tsx`,
`router.tsx`, the generated `routeTree`), and the exact `buzz-relay` code
path (`config.rs`'s `web_dir`/`serve_git_web_gui` flags, `router.rs`'s
`spa_fallback` and the `/` route's independent handling) that turns the
built bundle into what a browser receives at runtime.

**It does not cover, and these are gaps rather than silence:**

| Not covered here | Owned by |
|---|---|
| The container's full interface catalogue, deployment narrative, data implications, and security analysis | `architecture-containers-web` (`launchpad/docs/corpus/architecture/containers/web.md`) |
| Per-feature behavior of `web/src/features/repos/` (Git browser) and `web/src/features/invite/` (invite landing) -- routes, client libraries (`git-client.ts`, `nostr-client.ts`, `nip98.ts`), and their own realization detail | A sibling task in this same batch, `implementation/web/feature-map.md`, not yet merged at the recorded revision |
| The `admin-web/` bundle -- a separate source tree, build, and relay-side serve path (`BUZZ_ADMIN_WEB_DIR`, `is_admin_host`) | Not yet documented in this corpus; explicitly out of scope per `architecture-containers-web`'s own scope table |
| NIP-98, NIP-42, NIP-07, and NIP-11 as protocols in their own right | The Nostr NIPs themselves (https://github.com/nostr-protocol/nips) |
| Build/signing/deployment pipelines for the relay image this bundle ships inside | `squareup/sprout-oss` and `squareup/block-coder-tf-stacks`, private sibling repositories outside this corpus's reach |
