# Problem Record

## Problem Statement

_Clear, concise description of what is failing. Phrase as the symptom the customer or system sees, not the suspected cause._

## Known Error

_What component or service is affected, what its known-bad state or behaviour is, and how it differs from expected._

## Workaround

_Temporary action that restores service or bounds the blast radius. Empty if no workaround exists yet; under investigation otherwise. Do not block on the permanent fix._

## Current Blast Radius

_How many customers, regions, features, or systems are affected. Specify: affected count (users, requests/sec, % of traffic) and scope (feature, service, layer)._

## Next Diagnostic Step

_The single highest-yield investigation to run next. Phrase as a concrete action, not a guess ("check error logs for OOM" not "maybe a memory issue")._

## Owner

_Name and contact of the person responsible for this problem record and driving the investigation. This person updates it if status changes._
